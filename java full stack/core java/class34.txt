Inner classes 
=============
Sometimes we will declare a class inside another class such concept is called inner class.

syntax:
-------
	class Outer
	{
		class Inner 
		{			
			- //code to be execute 
		}
	}

Inner classes introduced in Java 1.1 version as a part of event handling to remove GUI bugs.

But due to powerful features and benefits of inner classes. Programmers started to use inner classes in regular programming.

Inner class does not support static members.

Inner class must and should declare with the scope of enclosing class.

We have four types of inner classes in java.

1) Normal/Regular inner class 

2) Static inner class 

3) Method local inner class

4) Anonymous inner class 


1) Normal/Regular inner class 
------------------------------
Sometimes we will declare a class inside another class without static keyword is called normal/regular inner class.

ex:
---
class Outer 
{
	class Inner 
	{
		public void methodOne()
		{
			System.out.println("Method One");
		}
	}
	public static void main(String[] args) 
	{
		Outer.Inner i = new Outer().new Inner();
		i.methodOne();
		
		//or
		new Outer().new Inner().methodOne();
	}
}
Note:
-----
	If we compile above program we will get two .class files i.e 
	Outer.class and Outer$Inner.class.
	

2) Static inner class 
---------------------
Sometimes we will declare a class inside another class using static keyword is called static inner class.

In regular/normal inner class, without existing container object there is no chance of having contained object.

ex:
---
class Outer 
{
	static class Inner 
	{
		public void methodOne()
		{
			System.out.println("Method One");
		}
	}
	public static void main(String[] args) 
	{
		Inner i = new Inner();
		i.methodOne();
	}
}

3) Method local inner class
----------------------------
Method local inner class is used to execute method specific repeated execution.

ex:
---
class Outer 
{
	public void m1()
	{
		class Inner 
		{
			public void sum(int a,int b)
			{
				System.out.println(a+b);
			}
		}
		Inner i = new Inner();
		i.sum(1,2);
		i.sum(10,20);
		i.sum(100,200);
	}
	public static void main(String[] args) 
	{
		Outer o = new Outer();
		o.m1();
	}
}

4) Anonymous inner class 
-----------------------
Sometimes we will declare a class without name such type of nameless class is called anonymous inner class.

ex:
---
interface ATM 
{
	public abstract void deposit();
}
class Test 
{
	public static void main(String[] args)
	{
		//anonymous inner class 
		ATM atm = new ATM()
		{
			public void deposit()
			{
				System.out.println("Deposit Method");
			}
		};
		atm.deposit();
	}
}

ex:
---
abstract class Payment
{
	public abstract void paymentMethod();
}
class Test 
{
	public static void main(String[] args)
	{
		Payment p = new Payment()
		{
			public void paymentMethod()
			{
				System.out.println("Credit Card");
			}
		};
		p.paymentMethod();
	}
}



Cloning 
=======
The process of creating exact duplicate object is called cloning.

We can perform cloning only for cloneable objects.

To create cloneable object our class must implements Cloneable interface.

Cloneable is a marker interface which does not have any methods and constants.

By using Cloneable interface we will get some ability to do by JVM.

To perform cloning we need to use clone() method of Object class.

ex:
	protected native Object clone() throws CloneNotSupportedException

ex:
---


class Test implements Cloneable
{
	//instance variable 
	int i = 10;
	
	public static void main(String[] args)throws CloneNotSupportedException
	{
		Test t1 = new Test();
		Test t2 = (Test)t1.clone();
		
		System.out.println(t1.i);
		System.out.println(t2.i);
		
		System.out.println(t1.hashCode()); //564742142
		System.out.println(t2.hashCode()); //90205195
	}
}


Q) What is difference between shallow cloning and deep cloning?

Shallow Cloning 
---------------
The process of creating exact duplicate object reference is called shallow cloning.

ex:
---


class Test 
{
	//instance variable 
	int i = 10;
	
	public static void main(String[] args)
	{

Types of objects 
================
We have two types of objects in java.

1) Immutable object 

2) Mutable object 

1) Immutable object 
-------------------
After object creation , if we perform any changes then for every change new object will be created such type of object is called immutable object.
ex:
	String  and wrapper classes 

In real life we will use immutable object when we won't allow to change the value of an object.
ex:
	Date of birth, PAN number, account number, aadhar No and etc.


2) Mutable object 
-----------------
After object creation, if we perform any changes then all the required changes will be done in a same object such type of object is called mutable object.
ex:
	StringBuffer and StringBuilder

In real life we will use mutable object when we allow to change the value of an object.
ex:
	Salary , bank balance, shopping cart and etc.

String 
======
It is a collection of characters enclosed in a double quotation.

case1:
------
Once if we create a String object we can't perform any changes. If we perform any changes then for every change a new object will be created such behaviour is called immutability of an object.

case2:
-----
What is the difference between == and .equals() method?

==
----
It is used for reference or address comparision.
ex:
--
class Test 
{

	public static void main(String[] args)
	{
		String s1 = new String("raise");
		String s2 = new String("raise");
		System.out.println(s1 == s2); // false 
	}
}


.equals()
---------
It is used for content comparision which is case sensitive.

ex:
---
class Test 
{

	public static void main(String[] args)
	{
		String s1 = new String("raise");
		String s2 = new String("raise");
		System.out.println(s1.equals(s2)); // true
	}
}

case3:
------
Once if we create a String object. Two objects will be created. One is on heap and another is on SCP(String Constant Pool) area. But 's' always points to heap area.

Diagram: class34.4

Object creations in SCP area is always optional.If JVM will check is there any object is created with same content or not. If it is created then JVM simply refers to that object. If it is not created then JVM will create a new object. Hence there is no chance of having duplicate objects in SCP area.

Even though SCP objects do not have any reference. Garbage collector can't access them.

SCP objects destroy automatically whenever JVM shutdowns or terminated.
